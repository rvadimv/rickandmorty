# Rick and Morty App


React-приложение для работы с Rick and Morty API.

Проект показывает список персонажей с поиском, фильтрами, пагинацией и страницей деталей. Основной акцент сделан на URL state, RTK Query, обработку состояний запроса и аккуратную работу с асинхронными данными.

## Функциональность

- Просмотр списка персонажей
- Поиск персонажей по имени
- Фильтрация по статусу
- Фильтрация по полу
- Пагинация
- Хранение поиска, фильтров и страницы в URL
- Корректная работа browser back / forward
- Детальная страница персонажа
- Возврат со страницы персонажа обратно к списку с сохранением фильтров
- Отображение первого эпизода в карточке персонажа
- Отображение списка всех эпизодов на детальной странице
- Skeleton-состояния загрузки для списка и детальной страницы
- Обработка состояний:
    - loading
    - error
    - empty result
    - not found

## Стек

- React

## Что демонстрирует проект

В этом проекте я сделал акцент не на количестве экранов, а на качестве работы с данными и состояниями интерфейса:

- URL как источник состояния для поиска, фильтров и пагинации;
- RTK Query для server state, кеширования и повторного использования запросов;
- batch-загрузку эпизодов вместо запроса из каждой карточки;
- отдельную обработку loading / error / empty / not found состояний;
- адаптивную сетку карточек и отдельную страницу деталей;
- сохранение состояния списка при переходе на страницу персонажа и обратно.

## API

Проект использует публичное API:

```txt
https://rickandmortyapi.com/api
```

Основные используемые ресурсы:

- `/character`
- `/character/:id`
- `/episode/:ids`

## Архитектура

Проект организован по упрощённому Feature-Sliced Design подходу.

Основные слои:

```txt
src/
  app/
  pages/
  entities/
  features/
  shared/
```

### `app`

Содержит базовую настройку приложения:

- роутинг
- store
- глобальные стили
- корневой layout

### `pages`

Содержит страницы приложения:

- страница списка персонажей
- детальная страница персонажа
- not found page

Страницы собирают данные, управляют состояниями запроса и соединяют entities/features/shared-компоненты.

### `entities`

Содержит бизнес-сущности приложения.

Например, сущность `character` содержит:

- типы персонажа
- API endpoints
- UI-компоненты карточки персонажа

### `features`

Содержит пользовательские сценарии.

Например:

- фильтрация персонажей

### `shared`

Содержит переиспользуемые части:

- UI-компоненты
- хуки
- утилиты
- общую обработку ошибок

## Работа с URL state

Поиск, фильтры и текущая страница хранятся в URL query params.

Пример:

```txt
/characters?name=rick&status=alive&gender=male&page=2
```

Такой подход позволяет:

- обновлять страницу без потери состояния
- использовать browser back / forward
- делиться ссылкой на конкретный результат поиска
- не хранить состояние фильтров отдельно в Redux

Input поиска использует локальное draft-состояние. Это нужно, чтобы не отправлять запрос на каждый введённый символ. URL обновляется только после подтверждения поиска.

## Работа с RTK Query

Для запросов используется RTK Query.

Реализованы запросы:

- получение списка персонажей
- получение персонажа по id
- получение эпизодов по id

Для карточек персонажей названия первых эпизодов загружаются отдельным batch-запросом. Это сделано для того, чтобы не отправлять отдельный запрос из каждой карточки.

Вместо этого страница:

1. получает список персонажей;
2. достаёт id первых эпизодов;
3. убирает дубли;
4. одним запросом получает нужные эпизоды;
5. передаёт название эпизода в карточку.

## Обработка состояний

В проекте отдельно обрабатываются основные состояния запроса:

- загрузка данных
- ошибка запроса
- пустой результат
- отсутствие найденной сущности

На странице списка персонажей toolbar с поиском и фильтрами остаётся видимым при ошибке или пустом результате.

На детальной странице персонажа используются ранние return-состояния, потому что вся страница зависит от данных одного персонажа.

## Детальная страница

Страница персонажа показывает основную информацию о персонаже и список эпизодов, в которых он появляется.

- изображение персонажа
- имя
- статус
- вид
- пол
- тип
- происхождение
- последнюю известную локацию
- первый эпизод появления
- список всех эпизодов, где встречался персонаж

Если пользователь пришёл на детальную страницу из списка, кнопка Back возвращает его обратно с сохранением поиска, фильтров и страницы.

Если пользователь открыл страницу напрямую, кнопка Back ведёт на список персонажей.
